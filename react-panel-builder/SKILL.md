# React Panel Builder

## Overview

Builds React admin panels using one fixed, battle-tested template. Do NOT invent new patterns or pull in other libraries — replicate the conventions in this skill exactly. Every panel uses: Vite + React 19 + TypeScript, Tailwind v4, axios api wrapper, Formik + Yup forms, react-router v7 routing with token auth, react-toastify feedback.

**Core principle: follow the template, do not redesign it.** Stable infra ships verbatim in `assets/`. Feature code (a new resource's list/form/filter) is generated by following the recipes in `references/`.

## Two Modes — pick first

```
Does the target project already have src/hooks/useListingApi.ts AND src/utils/api.ts?
  ├── NO  → init mode  (scaffold a full new project)
  └── YES → add mode   (add pieces, follow existing structure, never re-scaffold)
```

### init mode — fresh project
Follow `references/init-project.md`. Summary:
1. `npm create vite@latest <name> -- --template react-ts`
2. Install deps (exact set — see init reference, sourced from `assets/config/package.template.json`).
3. Copy `assets/config/*` over generated configs; copy `assets/src/*` into `src/`.
4. Set `.env` from `.env.example`. `npm run dev`.

Result: full working panel (auth + layout + dashboard + sample `listing` CRUD).

### add mode — existing project
1. Confirm project matches the template (api.ts, useListingApi, components/global/). If it diverges, follow whatever structure already exists — match it, don't fight it.
2. Build the requested piece via the recipe in `references/`. Most common ask = a new CRUD resource → `references/crud-resource.md`.

## Non-negotiable rules (apply in every mode)

- **API:** always go through `api.get/post/put/delete` (from `utils/api`). Pass `getAuthHeader(token)`. Check `if (res.failed) { notify.error(res.message); return }`. Never call axios/fetch directly in a page.
- **Listings:** always `useListingApi(url, token, { transformData, idExtractor, extraParams })`. Never hand-roll pagination/search state.
- **Tables:** always `DynamicTable` with a `tableStructure[]`. Never write raw `<table>`.
- **Forms:** always `FormBuilder` with `design: FormItem[]` + Yup `validationSchema` + `FormButtons`. Never hand-build form state.
- **Filters:** always `FilterBuilder` (`FormItem[]`) → push values into the listing's `setExtraParams`.
- **Feedback:** all success/error via `notify` (react-toastify).
- **Auth/token:** read from `useUserContext()`; never read localStorage directly.
- **Routing:** resources live at `/res` (list) + `/res/:id` (create/edit, where `id === "create"` means create). Wrap in `PrivateRoute`. Add a sidebar link in `DashboardLayout`.
- **Styling:** Tailwind utility classes + CSS vars (`--primary`, `--light-white`, `--light-text`). Use `cn()` to merge classes.

## Common mistakes

- Re-scaffolding when a project already exists → use add mode.
- Adding react-query/SWR/zustand/shadcn → not in this template; do not.
- Forgetting `transformData` in `useListingApi` → it throws; it is required, must map API response to `{ data, totalCount }`.
- Forgetting `idExtractor` → `add/update/remove` silently no-op without it.
- New route added but no `PrivateRoute` wrap or no sidebar link.

## Assets

`assets/` is the self-contained template source (`assets/src/` + `assets/config/`). It carries no brand images — branding is text-only via `components/global/Logo.tsx`, driven by `VITE_APP_NAME`. To brand a project, set `VITE_APP_NAME` or edit `Logo.tsx` to render a real image.
